🔧 הגדרת Firebase — שלב אחת ויש לך אפליקציה אמיתית!

כרגע הנתונים נשמרים רק בדפדפן שלך. כדי שכל העובדים יראו את אותם נתונים בזמן אמת, צריך לחבר Firebase (חינמי לחלוטין).

1
פתח Firebase Console
כנס לכתובת: console.firebase.google.com עם חשבון Google שלך
2
צור פרויקט חדש
לחץ "Add project" ← שם הפרויקט: textileops ← המשך עד סיום הקמת הפרויקט
3
הפעל Firestore
בתפריט הצד ← Build ← Firestore Database ← Create database ← בחר "Start in test mode" ← בחר אזור ← Done
4
קבל את פרטי ה-Config
הגדרות פרויקט (⚙) ← General ← "Your apps" ← לחץ על כפתור Web (</>) ← שם: textileops ← Register app ← העתק את האובייקט firebaseConfig
5
הכנס את ה-Config כאן
הדבק את הערכים מ-Firebase:
6
פרוס ל-Netlify (30 שניות)
כנס ל netlify.com ← הירשם עם Google ← גרור את קובץ ה-HTML לאתר ← קבל כתובת URL ← שלח לכל העובדים!

⚙️ הוצאות קבועות
הוצאות משתנות
חשבונית שמגיעה אחרי סוף החודש (הובלה וכד') — הזן את תאריך התשלום בשדה התאריך, ובחר את חודש השיוך כדי שתיזקף לחודש שאליו היא שייכת. ריק = לפי התאריך.
לחץ "חשב" כדי לראות תוצאות
👷 תעריף יומי לעובד
הזן שכר יומי לכל עובד — יחולק אוטומטית ל-8 שעות. הסעה וביטוח משמשים לחישוב "שעה עמוסה"
🕐 שעה עמוסה — הטבות והוצאות נלוות
העלות האמיתית של שעת עבודה: שכר + הסעה + פיצויים + ימי חג + מתנות + טיול + ביטוח. הסעה וביטוח מוזנים פר-עובד בכרטיס למעלה.
🏭 תקורה מפעלית לשעה
הוצאות קבועות (מהכרטיס למעלה) + ממוצע משתנות של החודשים האחרונים (לפי הבורר) + מרווח ביטחון — מחולק בסך שעות העבודה החודשיות של כל העובדים. בחר 1 כדי לחשב רק לפי החודש האחרון.
📝 סה"כ עלויות משתנות לפי חודש
הזן ידנית מנתונים אמיתיים (חשמל, מים, מטבח, ניקיון, רו"ח, מיסים...) — או חשב אוטומטית מההוצאות המשתנות שנרשמו
🧾 התחשבנות חודשית — משוער מול בפועל
לכל חודש: מה המקדם היה צופה (ממוצע עד 3 חודשים קודמים + מרווח ביטחון) מול מה שיצא בפועל. המקדם מתעדכן אוטומטית ככל שנוספים חודשים.

👤 ברקודים לעובדים
סרוק את הברקוד בסורק משימות במקום להקליד שם עובד
🔐 רק ברקודים מהאפליקציה
כל מדבקת משימה שהאפליקציה מדפיסה (וגם NFC) מקבלת סימון סודי בתוך ה-QR. כשהאכיפה פעילה, עובד ואחראי יכולים להתחיל משימה רק מסריקה של מדבקה כזו. QR שהוכן מחוץ לאפליקציה, מדבקה ישנה בלי סימון והקלדה ידנית של המספר — מנהל בלבד.
🏭 תחנות עבודה (מצלמות)
עובד סורק את ברקוד התחנה כשהוא מתיישב בעמדה — השיוך למחלקה ולתחנה נעשה אוטומטית ונרשם על המשימות. סריקת תחנה חדשה סוגרת את הקודמת; חתימת יציאה סוגרת הכל. הרשימה נלקחת מהמחלקות והתחנות שבלשונית ניהול — ערוץ DVR נקבע כאן (אותו ערוץ יכול לשמש כמה תחנות)
בהדלקה: עובד לא יוכל להתחיל משימה בלי לסרוק תחנה, ורק שלבים של התחנה שסרק (או תחנה באותו שם עם מספר אחר) יהיו זמינים. שלב בלי תחנה משויכת ייחסם — הרץ קודם "🔎 שלבים בלי תחנה". אחראי/מנהל יכולים לעקוף באישור. הכיבוי חל מיד על כל המכשירים.
🔧 מחלקות שבהן תחנה = מכונה (עובד אחד)
במחלקות המסומנות תחנה היא מכונה פיזית ועליה עובד אחד בלבד. עובד שסורק מכונה תפוסה — הסריקה האחרונה מנצחת: הקודם משוחרר מהתחנה והמשימות הרצות שלו נסגרות (מסירת המכונה = סיום). אחראי/מנהל שסורק לעצמו מכונה תפוסה נשאל קודם אם הוא עובד עליה או רק מחלק עבודה. מחלקות שאינן מסומנות (קבלה, גימור, אריזה) נשארות פתוחות לכמה עובדים יחד.
מוצא עובדים שרשומים כרגע על אותה מכונה ומשחרר את הישנים לפי זמן הסריקה. נחוץ לצמד ששויך לפני שהאכיפה עלתה — סריקה רגילה מתקנת רק מרגע הסריקה והלאה.
חל רק על שלבים שסומנו "🔗 מאחד" בכרטיס המוצר, ורק מולם — שלב רגיל אף פעם לא חוסם, וכל ההכנות המקבילות נשארות חופשיות. הבדיקה היא פר ברקוד (מידה+צבע). שלבים שנבחרו באותה סריקה לא חוסמים זה את זה. הרץ קודם "🔎 סדר שלבים בהיסטוריה" כדי לראות כמה היה נחסם.
בלי זה, שלב 🔗 שלא הסתיים ולו פעם אחת בהזמנה נחשב "שלב שלא סורקים" ואינו חוסם — כך אפשר להתחיל فحص قبل בלי ש-تنظيف בוצע. עם זה, כל שלב 🔗 חייב להסתיים על אותו ברקוד. חל רק על הזמנות שנפתחות מרגע ההדלקה — הזמנה שכבר רצה מסיימת בכללים שלפיהם התחילה, אחרת היא נעצרת מיידית. דורש שאכיפת הסדר למעלה תהיה דלוקה.
